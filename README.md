# • 🧠 Mem0

## 📦 1. Code and Data Preparation

This study builds upon the Mem0 framework, you can use the Mem0 framework code we provide. In addition, you also need to prepare other relevant datasets.

### 1.1. Framework: Mem0

- **Description**: A long-term memory framework for LLM-based agents.
- **Access**: [Mem0.ai/Mem0](https://github.com/mem0ai/mem0)  
  📄 *Mem0: Building production-ready ai agents with scalable long-term memory*, ECAI 2025.

### 1.2. Data: LoCoMo

- **Description**: A high-quality evaluation benchmark consisting of very long-term conversational data.
- **Access**: [ACL-2024/LoCoMo](https://github.com/snap-research/locomo)  
  📄 *Evaluating very long-term conversational memory of llm agents*, ACL 2024.

### 1.3. Data: LongMemEval

- **Description**: A comprehensive, challenging, and scalable benchmark for testing the long-term memory of chat assistants.
- **Access**: [ICLR-2025/LongMemEval](https://github.com/xiaowu0162/LongMemEval)  
  📄 *Longmemeval: Benchmarking chat assistants on long-term interactive memory*, ICLR 2025.

### 1.4. Data: PersonaMem

- **Description**: A personalization benchmark to assess how well language models can infer evolving user profiles and generate personalized responses across task scenarios.
- **Access**: [COLM-2025/PersonaMem](https://github.com/bowen-upenn/PersonaMem)  
  📄 *Know me, respond to me: Benchmarking llms for dynamic user profiling and personalized responses at scale*, COLM 2025.

### 1.5. Other Data

- **Description**: The original memories generated by the Mem0 framework for the above three datasets, as well as the compressed memories obtained under 30%, 50%, and 70% compression ratios.
- **Access**: [MemForest](https://huggingface.co/datasets/Celina-love-sweet/MemForest_data)  
  📄 *MemForest: Efficient Agent Memory Management via EventTree Partitioning and Progressive Merging*, Arxiv 2026.

For the latest Mem0 code, please refer to the links provided above. In addition, you do not need to download the three datasets separately. We have organized them into the LoCoMo dataset format, and the processed data can be obtained from the links above. ## ⚙️ 2. Environment Setup

We recommend using a Python virtual environment to avoid conflicts. Our implementation has been tested with `PyTorch 2.10.0+cu128`.


### 2.1. Create and activate a virtual environment (e.g., with conda):

```bash
conda create -n MemForest_Mem0 python=3.11
conda activate MemForest_Mem0
cd MemForest/Mem0
```

### 2.2. Install Python dependencies:

```bash
pip install -e ".[test,graph,vector_stores,llms,extras]"
```

---

## ✅ 3. Memory Compression

You can use our **MemForest** framework to compress the generated memory, as detailed below.

```bash
cd MemForest/Mem0/evaluation
python MemForest.py
```

You can control the dataset selection and the memory keep ratio by specifying the `DEFAULT_MEM_STORE_PATH` and `--keep-ratio` parameters. In addition, the LoCoMo, LongMemEval, and PersonaMem datasets contain 10, 500, and 222 sessions, respectively. You can use the `--start-idx` and `--end-idx` parameters to control the range of sessions to be compressed. For LongMemEval and PersonaMem, since they contain more sessions and require a longer compression time, we recommend following the method in `MemForest/utils/README.md`: first split the dataset, then compress each split separately, and finally merge the compressed results. Finally, **the compression results will directly overwrite the original memory files, so please make sure to back them up in advance**.

---

## 🚀 4. Inference

First, you need to fill in the `api_key` and `base_url` in `MemForest/Mem0/evaluation/config.example.json`.

You can run the framework using the generated memory with the following code.

```bash
CUDA_VISIBLE_DEVICES=0 python -u run_experiments.py --technique_type mem0 --method search
```
Note that you should modify the `dataset_path` parameter on line 59 and replace it with the path to the corresponding dataset. Meanwhile, please make sure that the `LOCAL_STORE_DIR` parameter on line 7 of `Mem0/evaluation/src/memzero/local_memory.py` is consistent with the dataset you are running, such as `locomo`, `locomo_keep30`, and so on. You can also modify the `start_idx` parameter on line 60 to specify the starting session. For example, for the LoCoMo dataset, it can be set from 0 to 9. This parameter is mainly used for resuming the program after an interruption. In this case, you can first remove the already processed data from `MemForest/Mem0/evaluation/dataset/locomo10.json`, and then modify `start_idx` to continue from the interrupted position.

---

## 🔍 5. Result Evaluation

You can obtain the final test accuracy by running the following code.

```bash
python evals.py --input_file results/mem0_results_top_30_filter_False_graph_False.json --output_file evaluation_metrics.json
python generate_scores.py
```

---

##  🛠️ 6. Memory Generation

If you need to regenerate the memories, please modify the `data_path` parameter on line 41 of `MemForest/Mem0/evaluation/run_experiments.py` and then run the following code:

```bash
CUDA_VISIBLE_DEVICES=0 python -u run_experiments.py --technique_type mem0 --method add
```

## ⚙️ 2. Environment Setup

We recommend using a Python virtual environment to avoid conflicts. Our implementation has been tested with `PyTorch 2.6.0+cu124`.


### 2.1. Create and activate a virtual environment (e.g., with conda):

```bash
conda create -n MemForest_M3_Agent python=3.11.14 -y
conda activate MemForest_M3_Agent
cd MemForest/M3_Agent
```

### 2.2. Install Python dependencies:

```bash
bash setup.sh
pip install qwen-omni-utils==0.0.4
pip install transformers==4.51.0
pip install vllm==0.8.4
pip install numpy==1.26.4
pip install flash-attn==2.6.3
```

---

## ✅ 3. Memory Graph Compression

You can use our **MemForest** framework to compress the memory graphs, as detailed below.

```bash
python MemForest.py
```

You can control the dataset selection, the memory keep ratio, and the saving path of the compressed memory graphs by specifying the `--mem_path`, `--keep-ratio`, and `--compressed_mem_path` parameters.

---

## 🚀 4. Inference

First, you need to fill in the `api_key` and `base_url` in `MemForest/M3_Agent/configs/api_config.json` and `MemForest/M3_Agent/config.example.json`.

You can run the model using the compressed memory graphs with the following code.

```bash
CUDA_VISIBLE_DEVICES=0,1 python -m m3_agent.control
```
Note that you should modify the `--data_file` parameter and replace it with the path to the compressed memory graphs.

---

## 🔍 5. Memory Graph Visualization

If you need to inspect the contents of the memory graphs, please run the following code.

```bash
python visualization.py
```

Note that the memory graph path specified by `--mem_path` should be replaced with the one you intend to inspect.

---

##  🛠️ 6. Memory Graph Generation

If you want to test other datasets, you need to regenerate the memory graphs. Please refer to the instructions provided by [ByteDance-Seed/M3-Agent](https://github.com/ByteDance-Seed/m3-agent).
